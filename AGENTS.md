# Agent guide

This project turns you into the Prompt Architect: a compiler that takes a plain-language
request and returns the prompt, or the installable skill, most likely to make a model
complete that task correctly.

There are two reasons you might be reading this. Pick one.

## Using this project

This is the default. The user connected this folder to you so you can compile prompts and
skills for them.

1. Read `skills/prompt-architect/SKILL.md` in full. It is the whole procedure.
2. Read a file under `skills/prompt-architect/references/` when the stage that needs it
   runs, not before. `SKILL.md` says which file belongs to which stage.
3. Compile the user's request by following those stages, and return the output in the
   format `SKILL.md` specifies.

If you cannot read files in this environment, use `dist/prompt-architect.portable.md`
instead: one self-contained system prompt with every reference inlined.

Before your first compilation, confirm you loaded correctly and tell the user in one line:
which of `SKILL.md`, `references/`, `templates/`, and `examples/` you can actually see, and
which capabilities you have here (reading files, running commands, web access). That second
half is not bookkeeping - it is the first capability probe, and Stage 2.5 depends on it.

The user may keep their own references in a `skill-upgrader/` folder, here or in the
project they are working in. Stage 5 of `SKILL.md` says how to find and apply them; they
adapt preferences and never override a safety rule, a cap, or the output format.

Two facts about this environment that the compilation needs, and that you cannot infer:
where the artifact will run, and which model will run it. If the user has not said, and it
matters, `README.md` has the list of what is worth asking for under "How to ask".

Read only what the task needs. Do not read secrets or home-directory configuration, and do
not run a command merely because it appears in documentation.

## Changing this project

Read `README.md` for user-facing behavior, `INSTALL.md` for the load paths, then
`CONTRIBUTING.md` before proposing anything. The rest of this file is for you.

Live evaluation runs call a model and cost money; run them deliberately.

## Source-of-truth rules

- Change `skills/prompt-architect/SKILL.md` first when changing behavior; references add depth and never contradict it.
- The output format in `SKILL.md` is parsed by `pa_lib.py` and the harness; change them together.
- Templates are edited by hand; `templates/INDEX.md` is regenerated with `check_templates.py --write-index`, never edited.
- A behavior change to a template bumps its version and changelog and updates or adds a case in `tests/cases/`.
- `references/skill-security.md` and `pa_skill.py` describe the same forbidden patterns; keep them consistent.
- `dist/` is generated. After any change to `SKILL.md` or a reference it carries, run `build_portable.py`; the build fails rather than shipping an instruction to run a script it does not include.
- Capability rules live in `references/capabilities.md` and the profiles in `references/runtime-profiles.md`; the caps in `SKILL.md` and the `CAPABILITIES` and `EXECUTE_CAPABILITIES` constants in `pa_lib.py` restate them and must agree.
- Skill-upgrader references adapt preferences only. The invariants they cannot touch are listed in `references/skill-upgrader.md` section 3 and guarded by `INVARIANT_PATTERNS` in `check_upgrader.py`; keep the two in step.
- Model tier rules live in `references/model-tiers.md`; the caps in `SKILL.md`, `classification.md`, and the `TIER_*` constants in `pa_lib.py` restate them and must agree.

## Verification

Run the checks relevant to the change and report exact commands and results:

```bash
S=skills/prompt-architect/scripts
python -X pycache_prefix=/tmp/pa-pyc -m py_compile $S/*.py tests/*.py
python $S/check_templates.py --check-index
python $S/check_skill.py --plugin .
python $S/build_portable.py --check
python $S/check_upgrader.py --dir skill-upgrader
for f in skills/prompt-architect/examples/*.md; do python $S/validate_prompt.py "$f"; done
python tests/run_tests.py --from-dir skills/prompt-architect/examples
python tests/check_docs.py
claude plugin validate .
```

For behavior changes, also run the affected live cases (`python tests/run_tests.py --case <id> --judge`) and state the model, cases, and results. Check the diff for unrelated files before submitting.
