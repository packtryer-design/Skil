# Working in this repository

This repository is the `prompt-architect` project: a prompt and skill compiler that any capable agent can load by reading `AGENTS.md`. A Claude Code plugin is one of four load paths, not the identity. The skill lives in `skills/prompt-architect/` (`SKILL.md`, `references/`, `templates/`, `examples/`, `scripts/`); plugin manifests are in `.claude-plugin/`; `tests/` is the evaluation harness; `evals/` holds native-format eval cases; `references/` at the root holds third-party projects studied (ignored by git); `dist/` holds generated single-file builds; `skill-upgrader/` holds user-added references that adapt generated output; `plan.md` and `references/planextention.md` are the specification. `AGENTS.md` is the full map.

Conventions:

- Keep `SKILL.md` self-sufficient and under about 500 lines; move depth into `references/`, never duplicate it.
- Generated prompts use the section catalog in `references/sections.md` in catalog order; generated skills follow `references/skill-authoring.md` and must pass `scripts/check_skill.py --generated` with zero errors.
- The capability layer is authoritative in `references/capabilities.md`, with per-runtime defaults in `references/runtime-profiles.md`. The caps in `SKILL.md` and the `CAPABILITIES`, `EXECUTE_CAPABILITIES` and `CAPABILITY_CLAIM_RE` constants in `scripts/pa_lib.py` restate them and must agree. Capability lint rules fire only on a capability stated explicitly, never on `unknown`, so a missing profile cannot produce findings.
- Skill-upgrader references (`skill-upgrader/`, in the working project or here) adapt preferences and never invariants; the list of invariants in `references/skill-upgrader.md` and `INVARIANT_PATTERNS` in `scripts/check_upgrader.py` must agree. Shipped samples live under `examples/` and are never applied.
- The model tier (`frontier`, `mid`, `small`, `tiny`) is a first-class axis: `references/model-tiers.md` is authoritative, and the caps repeated in `SKILL.md`, `references/classification.md`, and the `TIER_*` constants in `scripts/pa_lib.py` must agree with it. Every tier-specific lint rule is gated on a non-frontier tier so that default output cannot regress.
- `dist/` is generated by `scripts/build_portable.py`; run it after changing `SKILL.md` or any reference it inlines, and never edit `dist/` by hand.
- Templates carry the frontmatter documented in `references/template-authoring.md`; skill templates (category `skill`) hold `### <path>` headings with four-backtick fenced skeletons. After editing any template run `python skills/prompt-architect/scripts/check_templates.py --write-index`; never edit `templates/INDEX.md` by hand.
- Behavior changes to a template bump its version, add a changelog line, and update or add a case in `tests/cases/`.
- The output format in `SKILL.md` (summary keys, `## Prompt` fence, `## Skill` file blocks) is parsed by `scripts/pa_lib.py` and the harness; change them together.
- Validate before finishing (commands in `AGENTS.md`): compile the scripts with a pycache prefix outside the skill, `check_templates.py --check-index`, `check_skill.py --plugin .`, `build_portable.py --check`, `check_upgrader.py --dir skill-upgrader`, lint the examples, grade the examples offline, `python tests/check_docs.py`, and `claude plugin validate .`. Live runs (`python tests/run_tests.py --case <id>`) call a model and cost money; run them deliberately.
- Python is standard library only (3.11+); PyYAML is optional. Keep scripts ASCII-safe on Windows consoles. Large Markdown files are more reliably written with the Write tool than with shell heredocs in this environment.
